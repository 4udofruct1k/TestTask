# Облако для «Дома на двоих»

Покупки, готовка и остатки продуктов сводятся между двумя телефонами через
маленькую функцию в Яндекс Облаке. Бюджет туда не уходит никогда.

Как это работает: каждый телефон копит свои изменения («купил 900 г курицы»,
«в рагу ушло 1,6 кг картошки») и раз в сутки отправляет их функции. Функция
применяет их к общему состоянию строго по одному, сохраняет в базу и
возвращает телефону свежую общую картину. Если два телефона пришли
одновременно, второй подождёт, пока первый запишет, — ничего не теряется
и не удваивается.

Настройка — минут пятнадцать, с телефона в браузере. Делает один человек,
второму потом пересылается код одной строкой.

## Сколько стоит

При нашем объёме — 0 ₽. Функция вызывается несколько раз в день, база
хранит одну запись в десятки килобайт. Это далеко внутри бесплатного
уровня Cloud Functions и YDB. Карту Облако всё равно попросит привязать —
без платёжного аккаунта ресурсы не создаются.

## 1. Войти в консоль

Откройте **console.yandex.cloud** и войдите своим Яндекс ID. Если консоль
просит создать платёжный аккаунт — создайте. Облако и каталог `default`
появятся сами, всё дальше делается в этом каталоге.

## 2. База данных

1. В списке сервисов — **Managed Service for YDB** → **Создать базу данных**.
2. Имя — `household`. Тип — **Serverless**. Остальное не трогать → **Создать**.
3. Подождите, пока статус станет **Running** (минута-две).
4. На странице базы, во вкладке «Обзор», найдите **Эндпоинт Document API** —
   строку вида
   `https://docapi.serverless.yandexcloud.net/ru-central1/b1g…/etn…`.
   Скопируйте её целиком, она понадобится в шаге 4.

Таблицу создавать не нужно: функция создаст её сама при первом запросе.

## 3. Сервисный аккаунт

Это «пропуск», с которым функция ходит в базу. Ключей и паролей заводить
не нужно: функция получает пропуск автоматически.

1. В каталоге — **Сервисные аккаунты** (раздел Identity and Access
   Management) → **Создать сервисный аккаунт**.
2. Имя — `household-fn`.
3. **Добавить роль** → `ydb.editor` → **Создать**.

## 4. Функция

Сначала откройте в приложении **⚙ → Общие данные → Настраиваю сам →
Создать ключ** и скопируйте ключ. Его же вставите в функцию.

1. В списке сервисов — **Cloud Functions** → **Создать функцию**. Имя —
   `household` → **Создать**.
2. Откроется **Редактор**. Среда выполнения — **Node.js 22** (подойдёт
   и Node.js 18 или новее). Галочку «Добавить файлы с примерами кода» снимите.
3. Код — один из двух способов:
   - **ZIP-архив**: скачайте
     [function.zip](https://github.com/4udofruct1k/TestTask/raw/claude/repo-cleanup-hnmqr8/cloud/dist/function.zip)
     и загрузите его;
   - **Редактор кода**: создайте файл `index.js` и вставьте в него всё
     содержимое
     [cloud/dist/index.js](https://raw.githubusercontent.com/4udofruct1k/TestTask/claude/repo-cleanup-hnmqr8/cloud/dist/index.js).
4. **Точка входа** — `index.handler`.
5. **Таймаут** — 10 секунд, **память** — 128 МБ.
6. **Сервисный аккаунт** — `household-fn`.
7. **Переменные окружения** — две:

   | Ключ | Значение |
   |---|---|
   | `HOUSEHOLD_KEY` | ключ из приложения |
   | `DOCAPI_ENDPOINT` | эндпоинт из шага 2 |

8. **Сохранить изменения** — появится версия функции.

## 5. Открыть функцию для телефонов

На странице функции, во вкладке «Обзор», включите **Публичная функция**.
Там же — **Ссылка для вызова** вида
`https://functions.yandexcloud.net/d4e…`. Скопируйте её.

Проверка: откройте ссылку в браузере. Должно показать
`{"ok":true,"service":"household"}`. Без ключа функция ничего не отдаёт
и не принимает, поэтому публичная ссылка безопасна.

## 6. Подключить телефоны

**Свой телефон.** В приложении, там же, где создавали ключ: вставьте ссылку
на функцию → **Подключить**. Телефон сразу сведётся с облаком, внизу
появится «Сведено сегодня в …».

**Второй телефон.** На своём: **⚙ → Общие данные → Код для второго
телефона → Поделиться** и отправьте в мессенджер. На втором телефоне:
**⚙ → Общие данные → Мне прислали код** → вставить → **Подключить**.
Там же выберите, чей это телефон.

## Если не сводится

Текст ошибки виден в «Общих данных» и на главной.

| Сообщение | Что сделать |
|---|---|
| Нет связи с облаком | Интернета нет или ссылка неверная. Изменения лежат в телефоне и уйдут при следующей сводке |
| Облако не приняло ключ | `HOUSEHOLD_KEY` в функции не совпадает с ключом в приложении. Поправьте переменную и сохраните новую версию |
| В функции не задан ключ / DOCAPI_ENDPOINT | Не заполнена переменная окружения из шага 4 |
| У функции нет сервисного аккаунта | В редакторе функции выберите `household-fn` и сохраните версию |
| …AccessDenied… | У сервисного аккаунта нет роли `ydb.editor` (шаг 3) |
| …CreateTable… | Функции не удалось создать таблицу. Создайте сами: база → Навигация → Создать → **Документная таблица**, имя `household`, ключ партицирования `id` типа String |

## Как часто сводится

Сам телефон сводится раз в сутки: при первом открытии приложения после трёх
часов ночи. Сначала уходят свои изменения, потом приходят общие. Нужно
раньше — кнопка **Обновить** в «Покупках».

Пока приложение закрыто, оно не сводится: фоновой работы у него нет.
Поэтому утром, открыв приложение, вы получаете всё, что второй человек
успел отправить до этого.

## Обновить функцию

Если в репозитории поменялся код функции:

```
npm run build:cloud      # пересобирает cloud/dist/index.js и function.zip
```

и загрузите новый `function.zip` в редакторе функции. Переменные окружения
и сервисный аккаунт переносятся в новую версию сами.

## Что внутри

- `src/handler.ts` — приём очереди, ключ, повтор при одновременной записи.
- `src/docapi.ts` — база: два вызова Document API (GetItem и PutItem) с
  IAM-токеном функции, без SDK.
- `src/index.ts` — точка входа для Cloud Functions.
- `dist/` — собранный файл и архив для загрузки. Секретов в нём нет: ключ
  живёт только в переменных окружения функции и в телефонах.

Применение событий — тот же код, что в приложении (`src/household/apply.ts`),
поэтому телефон и облако считают одинаково.

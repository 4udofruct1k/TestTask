# Подсветка брони (max.armor-highlight)

Мод для «Мира танков» 1.45.0.0. Постановка задачи: [ARMOR_SPEC.md](ARMOR_SPEC.md).

**Статус: фазы 1 и 2 реализованы (MVP), в игре ещё не проверены.** В снайперском режиме по вражеской цели мод раскрашивает область вокруг круга сведения по результату ванильного расчёта пробития. Позиции квадратов обновляются каждый кадр, расчёт точек укладывается в бюджет кадра (см. «Решения» ниже). Фаза 0 отдельно не проверялась: если квадраты не видны, это и есть её вопрос.

## Сборка

Нужны Python 2.7 и 7-Zip.

```
build.bat -v 0.2.0
build.bat -v 0.2.0 -i "D:\Games\Tanki"
build.bat -v 0.2.0 -i "D:\Games\Tanki" -m 1.45.0.0
```

Первая команда только собирает `max.armor-highlight_0.2.0.mtmod` рядом с `build.bat`. С флагом `-i` скрипт копирует пакет в `<игра>\mods\<версия клиента>\`.

- Python ищется так: переменная `PYTHON27` (полный путь к `python.exe`), потом `py -2.7`, потом `python`. Версия проверяется, сборка на 3.x не пройдёт.
- Папку версии клиента внутри `<игра>\mods\` скрипт находит сам, если она одна. Иначе он выведет список, и папку нужно передать через `-m`.
- При установке скрипт удаляет из этой папки прошлые сборки `max.armor-highlight_*.mtmod`, чтобы клиент не загрузил две версии сразу. Перед установкой закрой игру.

## Что проверить в игре

Удобнее всего в тренировочной комнате с союзником в другой команде.

1. **Загрузка.** В `python.log` есть строки `[armor_highlight] init, version 0.2.0`, `avatar ready`, `started: toggle key KEY_Y, update every frame, frame budget 2.0 ms`.
2. **Появление.** Встань, перейди в снайперский режим и наведись на врага ближе 300 м. Через полсекунды вокруг прицела появятся цветные квадраты: зелёный — пробьёт, жёлтый — зависит от разброса, красный — не пробьёт. Цвет в центре должен совпадать с цветом ванильного маркера.
3. **Разные зоны.** Борт и лоб одной цели должны давать разную картину. Части цели за укрытием не красятся.
4. **Сведение.** Пока прицел сводится, подсветка тусклая и становится ярче по мере сведения. Дальше 200 м она постепенно гаснет и исчезает к 300 м.
5. **Движение камеры.** При повороте камеры квадраты должны держаться на броне, а не отставать от неё.
6. **Скрытие.** Подсветка сразу пропадает, когда ты едешь, выходишь из снайперского режима, уводишь прицел с цели или цель погибает.
7. **Клавиша Y** выключает и включает подсветку. В чате, а также с Ctrl, Alt или Shift нажатие не срабатывает.
8. **Лог.** Пока подсветка активна, раз в секунду пишется строка (числа для примера):
   ```
   stats 1.0s: frames=120 active=118 computed/frame=87.9 compute avg=1.18 max=2.09 ms, render avg=0.30 max=0.90 ms | grid=89 cell=10px green=6 yellow=3 red=6 undef=0 empty=74 pending=0 piercing=1
   ```
   - `computed/frame` меньше `grid` — сетка не влезает в кадр и пересчитывается за несколько кадров.
   - `compute` — расчёт точек (бюджет 2 мс), `render` — перестановка квадратов.
   - `green/yellow/red/undef` — результаты по точкам, `empty` — точки мимо цели или за укрытием, `pending` — ещё не посчитанные.
   Смены состояния пишутся строками `state: active` / `state: inactive, <причина>`. Один раз за бой пишется `segment dist check`: два числа в ней должны совпадать (сверка из фазы 1).
9. **FPS.** Сравни FPS с включённой и выключенной подсветкой.

Если квадратов нет совсем, но в логе `state: active`, значит, `GUI.Simple` не виден поверх интерфейса (вопрос фазы 0). В этом случае пришли лог, будем разбираться. Прежде всего попробую `cellTexture = ''` в `config.py`.

## Сверка API с клиентом 1.45.0.0

Раздел 3 спецификации сверен с `wot-src`, ветка `RU`, коммит `v.1.45.0.0 #2284`. Все имена и сигнатуры совпадают. Отдельно отмечено:

- Ванильный индикатор получает расчёт через `gun_marker_ctrl.createShotResultResolver()`. Эта функция возвращает тот же `_CrosshairShotResults`, потому что `_IS_EXTENDED_GUN_MARKER_ENABLED = True`. Мод вызывает её, а не приватный класс напрямую.
- Кроме `CLIENT` и `SERVER` в клиенте есть тип маркера `GUN_MARKER_TYPE.DUAL_ACC = 3`. Мод его не использует: берёт серверный маркер, если он включён, иначе клиентский.
- `gui.InputHandler.g_instance.onKeyDown` срабатывает раньше, чем чат обрабатывает клавиши. Поэтому мод проверяет фокус чата (`MessengerEntry.g_instance.gui.isFocused()`) и пропускает такие нажатия.
- В стандартной раскладке (`command_mapping.xml`) клавиша Y свободна.
- В `meta.xml` добавлен тег `<id>`: пакеты `.wotmod`, от которых произошёл `.mtmod`, опознаются по нему.

## Варианты отрисовки (исследование)

**Обводка техники не подходит.** Её рисует движок: `vehicle_systems/components/highlighter.py` вызывает `BigWorld.addEdgeDetectEntity(vehicle, collisions, colorIndex, drawMode, ...)`. Из Python можно только включить обводку для машины, выбрать один из четырёх глобальных цветов (`BigWorld.setEdgeDetectEdgeColor`) и режим отрисовки (`EdgeDrawMode`). Заливку силуэта за препятствиями (`overlay` — за непростреливаемыми, `destructible` — за разрушаемыми) задают `setEdgeDetectSolidColors` и `setEdgeDetectPatternColors`, цвета берутся из `<silhouetteColors>` в `scripts_config.xml`. Какую заливку показать, движок решает сам по типу препятствия, броня тут ни при чём. Раскрасить отдельные участки брони этим механизмом нельзя: вся машина получает один цвет.

**Наклейки на модель — отказались** (решение пользователя, см. «Решения» ниже). Так рисуются эмблемы, надписи и следы попаданий (`VehicleStickers.py`). `BigWorld.StickerModel(spaceID)`, затем `setupSuperModel(model, matrix)` и `addSticker(texName, bumpTexName, rayStart, rayEnd, sizes, rayUp, attributes)`: текстура проецируется на поверхность модели вдоль луча. Путь к текстуре произвольный, так что свои `.dds` можно положить в `.mtmod`, не трогая файлы клиента. Плюсы: подсветка лежит на броне, следует за моделью при повороте камеры, а перекрытие укрытиями решается буфером глубины. Что неизвестно: как движок выдержит 100–250 наклеек с пересчётом 10 раз в секунду (обычно на машине их десятки), и как правильно прикрепиться к частям модели цели (корпус, башня, орудие, ходовая).

Главный риск наклеек — видимость. Наклейка входит в материал модели, поэтому освещается как броня: в тени, ночью и в тумане цвет темнеет и сливается с камуфляжем. Флага «светится сам» среди `StickerAttributes` нет. Эмблемы по умолчанию пропадают дальше 70 м (`emblems/lodDist = MEDIUM`, `lodLevels` в `item_defs/vehicles/common/vehicle.xml`). У своей `StickerModel` дистанцию LOD можно задать через `setLODDistance`, но потолок движка неизвестен. На сильно наклонных листах проекция растягивается. У `GUI.Simple` этих проблем нет: яркость постоянная и от освещения не зависит.

## Решения, отличающиеся от ARMOR_SPEC.md

1. **Отрисовка только поверх экрана** (`GUI.Simple`). Наклейки и обводку не используем.
2. **Обновление каждый кадр** вместо раза в 0.1 с (раздел 2.5). `updateInterval = 0.0`: тик идёт через `BigWorld.callback(0, ...)`.
   - Позиции квадратов пересчитываются каждый кадр из сохранённых мировых точек попадания. Для этого матрица вида-проекции строится один раз за кадр, а не в каждом `cameras.projectPoint`. Подсветка держится на модели при повороте камеры. Это перепроецирование из фазы 3, теперь оно входит в фазу 2.
   - Лучи и расчёт пробития за кадр укладываются в бюджет `frameBudgetMs` (2 мс). Если вся сетка в него помещается, она пересчитывается целиком каждый кадр. Если нет, пересчёт растягивается на несколько кадров. Бюджет в 4 мс из спецификации был рассчитан на 10 пересчётов в секунду, а каждый кадр 4 мс при 100 FPS — это около 40% времени кадра.
   - Время в `python.log` пишется сводкой раз в секунду (среднее, максимум, число точек), а не на каждый пересчёт.

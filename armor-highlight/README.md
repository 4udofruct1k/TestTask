# Подсветка брони (max.armor-highlight)

Мод для «Мира танков» 1.45.0.0. Постановка задачи: [ARMOR_SPEC.md](ARMOR_SPEC.md).

**Статус: фаза 0 (каркас).** Мод загружается, пишет в `python.log` строки `init` и `avatar ready`, в бою показывает тестовые квадраты `GUI.Simple`.

## Сборка

Нужны Python 2.7 и 7-Zip.

```
build.bat -v 0.1.0
build.bat -v 0.1.0 -i "D:\Games\Tanki"
build.bat -v 0.1.0 -i "D:\Games\Tanki" -m 1.45.0.0
```

Первая команда только собирает `max.armor-highlight_0.1.0.mtmod` рядом с `build.bat`. С флагом `-i` скрипт копирует пакет в `<игра>\mods\<версия клиента>\`.

- Python ищется так: переменная `PYTHON27` (полный путь к `python.exe`), потом `py -2.7`, потом `python`. Версия проверяется, сборка на 3.x не пройдёт.
- Папку версии клиента внутри `<игра>\mods\` скрипт находит сам, если она одна. Иначе он выведет список, и папку нужно передать через `-m`.
- При установке скрипт удаляет из этой папки прошлые сборки `max.armor-highlight_*.mtmod`, чтобы клиент не загрузил две версии сразу. Перед установкой закрой игру.

## Фаза 0: что проверить в игре

1. Запусти бой (подойдёт тренировочная комната).
2. В центре экрана должен быть зелёный полупрозрачный квадрат 96×96 px: это `GUI.Simple('')`. Правее, на расстоянии своей ширины, — красный квадрат того же размера: `GUI.Simple` с белой текстурой движка `system/maps/col_white.dds`. Если первый не виден, а второй виден, для отрисовки будем брать текстуру.
3. Линии прицела должны рисоваться **поверх** квадратов: оверлей стоит на глубине `0.7`, между прицелом (`0.6`) и маркерами техники (`0.9`).
4. В `python.log` должны появиться строки с префиксом `[armor_highlight]`: `init, version 0.1.0`, `avatar ready`, `screen size: ...`, две строки `test square: ...`. После выхода из боя — `avatar become non-player`. При повторном входе в бой квадратов по-прежнему два.

## Сверка API с клиентом 1.45.0.0

Раздел 3 спецификации сверен с `wot-src`, ветка `RU`, коммит `v.1.45.0.0 #2284`. Все имена и сигнатуры совпадают. Отдельно отмечено:

- Ванильный индикатор получает расчёт через `gun_marker_ctrl.createShotResultResolver()`. Эта функция возвращает тот же `_CrosshairShotResults`, потому что `_IS_EXTENDED_GUN_MARKER_ENABLED = True`. В фазе 1 мод будет вызывать её, а не приватный класс напрямую.
- Кроме `CLIENT` и `SERVER` в клиенте есть тип маркера `GUN_MARKER_TYPE.DUAL_ACC = 3`.
- `gui.InputHandler.g_instance.onKeyDown` срабатывает раньше, чем чат обрабатывает клавиши. Значит, Y в чате тоже переключит подсветку. В фазе 2 такие нажатия нужно отфильтровать.
- В стандартной раскладке (`command_mapping.xml`) клавиша Y свободна.
- В `meta.xml` добавлен тег `<id>`: пакеты `.wotmod`, от которых произошёл `.mtmod`, опознаются по нему.

## Варианты отрисовки (исследование)

**Обводка техники не подходит.** Её рисует движок: `vehicle_systems/components/highlighter.py` вызывает `BigWorld.addEdgeDetectEntity(vehicle, collisions, colorIndex, drawMode, ...)`. Из Python можно только включить обводку для машины, выбрать один из четырёх глобальных цветов (`BigWorld.setEdgeDetectEdgeColor`) и режим отрисовки (`EdgeDrawMode`). Заливку силуэта за препятствиями (`overlay` — за непростреливаемыми, `destructible` — за разрушаемыми) задают `setEdgeDetectSolidColors` и `setEdgeDetectPatternColors`, цвета берутся из `<silhouetteColors>` в `scripts_config.xml`. Какую заливку показать, движок решает сам по типу препятствия, броня тут ни при чём. Раскрасить отдельные участки брони этим механизмом нельзя: вся машина получает один цвет.

**Кандидат для фазы 3 — наклейки на модель.** Так рисуются эмблемы, надписи и следы попаданий (`VehicleStickers.py`). `BigWorld.StickerModel(spaceID)`, затем `setupSuperModel(model, matrix)` и `addSticker(texName, bumpTexName, rayStart, rayEnd, sizes, rayUp, attributes)`: текстура проецируется на поверхность модели вдоль луча. Путь к текстуре произвольный, так что свои `.dds` можно положить в `.mtmod`, не трогая файлы клиента. Плюсы: подсветка лежит на броне, следует за моделью при повороте камеры, а перекрытие укрытиями решается буфером глубины. Что неизвестно: как движок выдержит 100–250 наклеек с пересчётом 10 раз в секунду (обычно на машине их десятки), и как правильно прикрепиться к частям модели цели (корпус, башня, орудие, ходовая).

Главный риск наклеек — видимость. Наклейка входит в материал модели, поэтому освещается как броня: в тени, ночью и в тумане цвет темнеет и сливается с камуфляжем. Флага «светится сам» среди `StickerAttributes` нет. Эмблемы по умолчанию пропадают дальше 70 м (`emblems/lodDist = MEDIUM`, `lodLevels` в `item_defs/vehicles/common/vehicle.xml`). У своей `StickerModel` дистанцию LOD можно задать через `setLODDistance`, но потолок движка неизвестен. На сильно наклонных листах проекция растягивается. У `GUI.Simple` этих проблем нет: яркость постоянная и от освещения не зависит. Поэтому основной путь — `GUI.Simple`, а наклейки — только эксперимент со сравнением в бою.
